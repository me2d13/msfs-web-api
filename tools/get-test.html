Format

SimVars and client data fields share the |alias suffix, so the JSON key can be shorter than the name.

FormExampleMeaning
VARPLANE ALTITUDEordinary SimVar, key = SimVar name
VAR|aliasPLANE ALTITUDE|ALTordinary SimVar, key = ALT
CLIENT:area:offset:typeCLIENT:PMDG_NG3_Data:0x1AD:boolbytes at offset in the area, read as type
CLIENT:area:offsetCLIENT:PMDG_NG3_Data:0x74same, default type double
CLIENT:area@id:offset:typeCLIENT:MyAddOn@0x1234:0:floatexplicit area ID for add-ons not in the registry

Types: bool / byte, int8, int16, uint16, int32, uint32, int64, uint64, float, double. Offsets may be hex (0x1B5) or decimal. Client data is read-only; a missing area (add-on not loaded, broadcast off) returns null in the JSON (the value is NaN internally). Without an alias the key defaults to area:offset.

PMDG offsets in the presets come from the field order in PMDG_NG3_SDK.h (EnableDataBroadcast=1 in 737NG3_Options.ini is required). Derive them with C alignment in mind - a missed unsigned short shifts every following field. The presets were checked against a live 737: 0x1A4 speed window, 0x1AC heading, 0x1AE altitude, 0x1B5 A/T arm switch, 0x1BA A/T arm light.
